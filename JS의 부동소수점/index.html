JS의 부동소수점
Javascript
2026.01.12.

⛳️ 개요

회사에서 계산 로직을 프론트에서 수행할 때도 있는데, 사칙연산 결과가 소수점이 되는 경우 생각하지 못한 결과값이 나오게 되었는데 세금 신고까지 잘못 발생된 적이 발생한 적이 있다.
그래서 잘못 계산되는 원인이 무엇인지 학습한 내용을 정리해본다.

📍본론

내가 주로 겪었던 문제는 소수점 덧셈에서 예상하지 못한 결과가 나왔다.
0.1 + 0.2 = 0.3 결과가 나올 것을 예상했지만, 실제로는 0.30000000000000004 결과 값이 나온다.
마찬가지로 10 / 3은 3.3333333333333335 결과가 나온다.

🧐 왜 이런 값이 나올까?

결론적으로, Javascript에서 숫자는 IEEE754 표준에서 정의한 64비트로 인코딩된 배정밀도의 부동소수점(doulbe-parsing floating-point) 형식을 사용하기 때문이다. 즉, IEEE74는 숫자를 2진수 기반으로 표현되고 가수부(소수점이하)는 정규화된 가수의 52비트까지만(53비트에서 반올림) (-2⁵³ ~ 2⁵³) 저장하기에 오차가 발생한다.

[ 부호(sign) | 지수(exponent) | 가수(fraction) ]
[    1bit     |    11bit      |    52bit       ]

0.1을 2진수로 나타내보자(= 소수점 이하는 2를 곱함)

0.1 * 2 = 0.2 -> 0
0.2 * 2 = 0.4 -> 0
0.4 * 2 = 0.8 -> 0
0.8 * 2 = 1.6 -> 1
0.6 * 2 = 1.2 -> 1
0.2 * 2 = 0.4 -> 0
0.4 * 2 = 0.8 -> 0
0.8 * 2 = 1.6 -> 1
0.6 * 2 = 1.2 -> 1
0.2 * 2 = 0.4 -> 0
...

= 0.0001100110011…₂

결과는 0.0001100110011…₂라는 무한 2진수가 나왔지만, IEEE754 저장값은 아래 와 같은 개념으로 저장된다.

value = (-1)^sign × (1 + fraction / 2^52) × 2^(exponent - bias)

즉 1.1001100110011001100110011001100110011001100110011010 × 2⁻⁴ 으로 저장되고, 이걸 10진수로 출력하면, 0.1000000000000000055511151231257827021181583404541015625으로 표현된다.

0.2도 마찬가지로 10진수 0.2000000000000000111022302462515654042363166809082031250로 표현되므로, 이를 더하면, 0.30000000000000004라는 근사값이 나온다. 따라서, 0.1 + 0.2 != 0.3이라는 결과 값을 알 수 있다.

📚 심층

하지만, 사칙연산이 무조건 정확하지 않은것은 아니다.
정확히 떨어질 조건은 아래와 같다.

 - 이진수로 유한한 소수 ex) 0.5, 0.25, 0.75 ...
 - 반올림 결과가 정확히 일치하는 경우
 - 계산 결과가 2⁵³ − 1 이하인 경우

안 떨어지는 조건은 아래와 같다.

- 이진수 무한한 소수 ex) 0.1, 0.2, 0.3 ...
- 계산 결과가 2⁵³ - 1 초과한 경우

이러한 이유로 Javascript에서 숫자와 관련한 연산을 할 때, 정확한 결과값이 나오는지 판별할 수 있어야한다.

💡 결론

Javascript 뿐만 아니라, 부동소수점을 사용하는 모든 언어도 이러한 현상이 있다.
이런 오류를 해결하면 toFixed()나 Math.round()를 이용해서 할 수는 있지만, 개인적으로 이것도 계산이 틀어지는 경우가 있었다.

따라서 나는 Big.js 라이브러리를 사용하는 걸 선호한다.
물론 라이브러리라보니 덧셈,뺄셈 등 제공하는 함수와 계산 방식을 사용해야 한다는 단점이 있지만,
계산 결과가 정확하기에 이런 단점은 단점이 아니라고 생각한다😀
